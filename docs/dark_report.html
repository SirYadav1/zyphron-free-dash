2. PROJECT VISION & OBJECTIVES

2.1 The Problem

Game server hosting is expensive. Most providers charge $5-20/month for basic servers. Many gamers, especially in developing countries, cannot afford these costs. Zyphron Cloud solves this by offering free hosting through a credits-based economy.

2.2 The Solution

Zyphron Free Dashboard -- a platform where users earn credits through daily logins, AFK sessions, and a coin shop. These credits are used to deploy and manage game servers via Pterodactyl Panel integration.

2.3 Core Objectives

  • Provide FREE game server hosting through credits economy
  • Integrate with Pterodactyl Panel for server management
  • Modern, professional dark-theme UI/UX
  • Complete admin panel with 15+ management pages
  • Discord OAuth for easy authentication
  • Security best practices throughout the stack
  • Self-hosted on a single VPS (no external dependencies)
  • Scalable architecture for future growth

6. ARCHITECTURE & TECHNICAL DESIGN

6.1 System Architecture

User (Browser)
    |
    v
Nginx (Port 8080) ----> Vue 3 SPA (Static Files)
    |
    v
Nginx /api/* ----> NestJS Backend (Port 3000)
    |
    v
TypeORM ----> SQLite (zyphron.db)
    |
    v
Pterodactyl API ----> Game Servers

6.2 Request Flow

  1. User opens browser -> Nginx serves Vue 3 SPA (index.html)
  2. SPA loads -> Vue Router handles client-side routing
  3. API call -> Axios sends request with JWT Bearer token
  4. Nginx proxies /api/* to NestJS backend (port 3000)
  5. JwtAuthGuard verifies token -> AdminGuard checks role
  6. Controller processes request -> Service handles business logic
  7. TypeORM queries SQLite database
  8. Response returned to frontend
  9. Pinia store updates -> Vue reactivity re-renders UI

6.3 Authentication Flow

1. User submits email + password
2. AuthService validates credentials (bcrypt.compare)
3. If valid: sign JWT with { sub: userId }
4. Return { access_token, user object }
5. Frontend stores token in sessionStorage
6. Axios interceptor adds Authorization: Bearer [token]
7. JwtAuthGuard verifies token on protected routes
8. AdminGuard checks is_admin flag for admin routes

6.4 Pterodactyl Integration (3-Step Sync)

Step 1: Try to find user by email on Pterodactyl
Step 2: If not found, try by username
Step 3: If still not found, create new Pterodactyl account

This ensures maximum compatibility:
- Existing panel users get linked automatically
- New users get auto-created on the panel
- Dashboard works even if panel is unreachable

High Priority Bugs

Coin Order Race Condition

No optimistic locking on coin order approval. Fixed by adding WHERE clause.

XSS in Ticket Close

User comments rendered unescaped in HTML. Fixed with escapeHtml().

Route Conflict

GET /api/servers/expiring broken by ParseIntPipe. Fixed by reordering routes.

Admin Modals Dead Code

Edit/Roles modals never opened. Fixed by adding trigger buttons.

AFK Session Leak

Admin logout didn't stop AFK. Fixed by adding afkStore.stopSession().

13. CHALLENGES FACED

Pterodactyl API Integration

The Pterodactyl API required complex 3-step sync logic. Users could exist on the panel but not in the dashboard, or vice versa. Solution: email -> username -> create fallback.

Coin Economy Race Conditions

Multiple concurrent coin operations could cause double-spending. Solution: Optimistic locking with WHERE coins = :currentCoins on all coin updates.

CORS Configuration

Balancing security with development convenience. Solution: Environment-aware CORS that allows localhost in dev but restricts to specific origins in production.

Admin Panel Complexity

The admin panel grew to 15+ pages, each with CRUD operations. Solution: Consistent patterns with shared components.

SQLite Limitations

SQLite doesn't support concurrent writes well. Solution: Optimistic locking and sequential access patterns for critical operations.

18. LESSONS LEARNED

Start with Security

Security should be built in from day 1, not bolted on later. The initial codebase had 30+ security issues that had to be fixed.

Optimistic Locking is Essential

Any concurrent state modification needs optimistic locking. Without it, race conditions cause data corruption.

Test Early, Test Often

The 40-bug scan on Day 5 could have been caught earlier with continuous testing.

Mobile-First Design

Admin panels are often used on phones. Design mobile-first, then enhance for desktop.

Night Sessions Are Powerful

5 night sessions produced the most critical work. Deep focus without interruptions leads to rapid progress.
